# Data Workflow Manager v0.1.8-a3 – dockbar Qt-arbeidsflate

## Formål

Første **selvstendige PySide6-frontend** med fleksible, brukerstyrte paneler.
Dette er en ny GUI-implementasjon – ikke en oppbygging på den gamle CustomTkinter-arvekjeden.

## Oppstart og test

1. Pakk a3-deltaen over lokal **v0.1.8-a2**. Deltaen inneholder bare prosjektfiler.
2. Installer GUI-krav: `py -m pip install -r requirements-gui.txt` (eller `install.bat gui`).
3. Kjør `test.bat`.
4. Kjør `start.bat` for **Qt-GUI**. `start-legacy.bat` starter **tidligere CustomTkinter-GUI**.
5. Alternativt: `py -m gui_qt "C:\sti\til\jobbliste.n5jobs"`.

## Implementert

- Eget Qt-startpunkt (`gui_qt`) og en GUI-uavhengig arbeidsflate-API (`app/workbench_api_v018_a3.py`).
- Qt-dockpaneler: **Jobber**, **Arbeidsflyt**, **Kilde og lagring**, **Kjøreløp og logg**, **Hjelp og informasjon**.
- Paneler kan flyttes til **alle fire sider**, gjøres til faner, skjules, frikobles til eget vindu og flyttes mellom skjermer.
- Ferdige visningsmoduser: **Laptop**, **Analyse**, **Depot**, **Full**, **Workshop**, **Topp og bunn**.
- Kompleksitetsnivåer: **Enkel**, **Standard**, **Avansert**.
- Egne navngitte arbeidsflater lagrer panelplassering, kompleksitet og aktiv fane, og kan gjenopprettes; siste vindusstilling lagres ved avslutning.
- Skjermgjenoppretting ved frakobling; flytende vinduer plasseres synlig på gjenværende skjerm.
- Last inn eksisterende `.n5jobs`, se flere jobber, velg aktiv jobb, inspiser utførelsesrekkefølge.
- Opprett jobb, velg en konfigurasjonsstyrt Noark 5-arbeidsflyt, kontrollpunkt og uavhengige lagringsroller.
- Lagre jobblister med **eksisterende format 4**, uten å kopiere eller flytte uttrekk.
- Kjør én jobb med `A39JobRunner` via `DwmApplication` fra a1, fortsett ved kontrollpunkt eller kjør alle klare sekvensielt. Kjøring skjer på egen Python-tråd, GUI poller hendelseskø på Qt-tråden.
- Vis og åpne eksisterende resultater via en **lazy** `QFileSystemModel` (ingen automatisk rekursiv traversering av dokumentfiler).
- Egen knapp for å starte tidligere GUI for fortsatt avansert depotvurdering, batchfunksjoner og spesialdialoger.

## Bevisste avgrensninger – viktig til workshop

- Første a3 har **ikke alle funksjoner fra v0.1.7-GUI**: flerjobb-batchstrategier, avansert rapportgenerator, redigering av depotvurdering, Arkade 5-dialoger, mottak/ingest og avansert metadatahåndtering åpnes foreløpig via det gamle GUI-et.
- `Kjør klare jobber` er **sekvensiell**; den er ikke en erstatning for eksisterende parallell batchmotor.
- GUI-et bruker **allerede implementert** underliggende Noark 5-utførelse, men har ikke en ny separat persistent worker-prosess. DWM-programmet skal derfor ikke avsluttes under aktiv kjøring.
- `source_root`, `source_extraction`, `work_content`, `work_operations` og `archive_root` er uavhengige. Lagringsredigering endrer kun jobbkonfigurasjon, ikke disker/uttrekk.
- Pågående kjøringer må avsluttes før en ny jobbliste åpnes eller GUI-et lukkes.
- Nettverksuttrekk og diskbrudd er ikke praktisk prøvd med Windows i utviklingsmiljøet. Utfør en reell workshop-maskin-test.

## Manuell godkjenningskontroll

1. Start Qt-GUI på 1366×768, 125/150 % skalering.
2. Åpne `Test-documaster-01.n5jobs` og velg JOB-001 / JOB-002; verifiser Source, Work og AIP.
3. Prøv **Vis → Arbeidsflate → Laptop / Analyse / Depot / Workshop**.
4. Dra paneler til topp, bunn og begge sider. Frikoble ett, flytt til skjerm 2, lagre arbeidsflaten, lukk og åpne igjen.
5. Skru av skjerm 2, og verifiser at frikoblet panel fortsatt er tilgjengelig.
6. Åpne **Resultater / filer → Vis filer**; bekreft at eksisterende DWM-rapportmapper vises.
7. Test **Kjør valgt** på en kopi av et lite uttrekk, ikke på eneste depotarbeidskopi. Avbrudd er kooperativt.
8. Start `start-legacy.bat` og kontroller at gammel jobbliste, metadata og depotvurdering fortsatt fungerer.

## Arkitektur

- `app/application_api.py` fra a1: åpne/lagre jobbliste, jobbsnapshot, hendelser, `A39JobRunner`, avbrudd.
- `app/workbench_api_v018_a3.py`: GUI-uavhengig lesemodell og eksplisitte kommandoer for jobb-, arbeidsflyt- og lagringsredigering.
- `gui_qt/main_window.py`: Qt-presentasjon, dockplassering, brukerpreferanser og visning. Ingen innlemming i historiske `persistent_app_a*`-klasser.
- `QSettings("IKAMR", "DWM-Qt")` lagrer **kun GUI-innstillinger**, atskilt fra jobbdata og repo.

## Tilbakerulling

- `start-legacy.bat` starter eksisterende GUI direkte.
- For å gjøre det gamle GUI-et til standard igjen kan `start.bat` fra a2 gjenopprettes.
- a3 endrer ikke `main.py`, eksisterende GUI-runtime, Noark 5-operasjoner eller jobbfilformat.
