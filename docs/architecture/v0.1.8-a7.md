# v0.1.8-a7 – Setup og Arkade 5 CLI-kontroll

## Hensikt

Det nye PySide6-grensesnittet skal kunne konfigurere DWM uten å åpne gamle
CustomTkinter-vinduer. Operasjoner som krever Arkade 5 CLI skal ikke starte
med manglende eller feil konfigurert programfil.

## Felles Setup

Meny `Fil → Setup` og knapp `Setup` i verktøylinjen åpner dialogen.
Den bruker eksisterende `config.json`/`settings.save_config` via
`DwmWorkbenchAPI.save_setup`, ikke en separat Qt-konfigurasjon.

Dialogen viser:

- Arkade 5 CLI-programfil med manuell filvelger og begrenset automatisk søk.
- CLI-versjonskontroll, med kort tidsgrense og responsivt GUI.
- Standard Noark 5-arbeidsflyt for **nye** jobber.
- Arkade 5 resultat-undermappe, DWM-undermappe under Work og Temp-mappe.

Ingen funn eller test endrer oppsettet automatisk. Brukeren må velge **Lagre
Setup**. Endring av Work-undermappen krever egen bekreftelse fordi eksisterende
resultatstier kan påvirkes. Ingen Source-filer, resultatfiler eller jobblister
flyttes eller slettes.

## Førkjøringskontroll

`DwmWorkbenchAPI.preflight_job` integrerer nå
`Arkade5DependencyChecker`. Det er operasjons-ID-ene i **den aktuelle jobben**
som avgjør om CLI er påkrevd:

- `arkade5_noark5_test`: CLI påkrevd.
- `arkade5_pronom_analysis`: CLI påkrevd.
- `import_arkade5_reports`: CLI **ikke** påkrevd, fordi denne importerer
  allerede eksisterende rapporter.

Hvis CLI ikke er konfigurert, programfilen mangler, er relativt angitt, ikke
kan startes eller gir en timeout, blokkeres jobbstart. Når programmet kan
startes, men versjonen bare kan utledes fra programmappen, programidentiteten
er usikker, eller versjonssjekken returnerer en feilstatus, vises et avvik som
krever samtykke. Kontroll av versjon er ikke det samme som en faktisk test av
et Noark 5-uttrekk.

Kontrollen gjentas på API-grensen ved kjøring. GUI tilbyr Setup ved CLI-feil,
men kjøringen startes ikke automatisk etter en konfigurasjonsendring.

Førkjøringsplanen er lesende. `PreflightReport.ready` er **False** ved feil,
manglende godkjent mappehandling **eller advarsler** som må bekreftes.

## Verifikasjon

Nye a7-tester dekker CLI-krav per operasjon, manglende/relative feil, CLI-test,
versjonsusikkerhet, caching, installasjonsfunn, API-sperre, felles Setup-lagring
og GUI-kontraktene. Eksisterende a6-tester for Source, Work og AIP kjøres som
regresjonskontroll.

Qt-vinduer må fortsatt verifiseres på Windows med PySide6 installert. Legacy-GUI
og DWM-arbeidsmotor er ikke endret i a7.
