# DWM v0.1.9-a2 - depotvurdering per uttrekk og arkivdel

Utgangspunkt: v0.1.9-a1 med a1-fix1. Dette trinnet bygger videre på
Resultatvisninger uten å endre eksisterende Noark 5-analyser eller rapportmotorer.

## Ny arbeidsflate i PySide6

- Rapport > Depotvurdering... og Depot / rapport > Depotvurdering... åpner
  Resultatvisninger med Depotvurdering-fanen valgt.
- Uttrekk og deres arkivdeler vises hierarkisk for valgt(e) Work-jobber.
- Filtrering: alle, trenger faglig vurdering, vurderte, manglende/usikkert
  grunnlag; i tillegg fritekstsøk.
- Teknisk status, vurderingspunkter, periodevurdering, faglig depotbeslutning
  og tidspunkt vises som **ulike** felt. 9/9 fullførte deljobber gir aldri
  automatisk depotgodkjenning.
- Detaljer viser rapportens egne fakta og separate referanser til DWM,
  Arkade 5, PRONOM og KDRS Query fra a1-kildeoversikten. Ukjent er ikke 0.
- Bruker kan gå til eksisterende faglig periodevurdering, åpne konkret
  kilderapport eller registrere en egen depotbeslutning.

## Eksisterende faglig motor er bevart

**Hele uttrekket:** `noark5_workflow.analysis.depot_assessment` brukes direkte
(`load_depot_assessment` og `record_depot_assessment`). Alle de fire etablerte
statusene, obligatorisk begrunnelse, UserIdentity, full historikk,
SHA-256-binding og vurdert HTML/JSON-rapport er uendret. Generert
`assessment.status` i en depotrapport er ikke bevis for en manuell beslutning.

**Periodevurdering:** Eksisterende `period_assessment_a16` for uttrekks- og
arkivdelsnivå åpnes fra Depotvurdering. Den er ikke omdefinert til
full faglig depotgodkjenning.

## Nytt for arkivdeler

`app/depot_review_v019_a2.py` skriver bare ved **eksplisitt, bekreftet**
registrering, via GUI-uavhengig API `record_part_decision(...)`.

Lagres ved siden av den konkrete opprinnelige depotrapporten i Work:

    noark5_reports/depot_validation/<RUN>/
      depot_validation_report.json           # uendret original
      depot_assessment.json                  # eksisterende vurdering av uttrekk
      depot_assessment_parts.json            # ny arkivdelsvurdering

Den nye filen har formatversjon, rapportens SHA-256, kjørings-ID,
varig jobbidentitet og en selvstendig historikk for hver arkivdels **native
system-ID**. Ingen sammenkobling ved listeløpenummer, tittel eller KDRS U2-indeks.

Eldre vurderinger bevares ved nye beslutninger. Endret rapportinnhold,
manglende/duplisert arkivdel-ID, skadet vurderingshistorikk og feil Work-UUID
blokkerer skriving. Tilgang til Source og AIP er ikke nødvendig.

De nye arkivdelbeslutningene vises i Qt-fanen. Innfletting av disse nye
beslutningene i alle de historiske rapportfamiliene er **ikke** implementert
i a2 og krever en egen kontrollert rapporteringsendring senere.

## Identitet og ansvar

Qt bruker den eksisterende lokale DWM-brukerprofilen via
`LocalUserProfileIdentityProvider`. Brukerprofil kan registreres/endres i Qt
med DWM sin etablerte `save_user_profile`; stabil bruker-ID beholdes.
Beslutninger krever valgt status, begrunnelse og bekreftelse. Ny profil gir
ikke automatisk faglig godkjenning. Dersom Work/rapport mangler, kan
informasjon vises som ukjent, men skriving blokkeres.

## Akseptansetest på Windows

1. Installer a2 over v0.1.9-a1 inkludert siste fix1. Kjør `test.bat`.
2. Start `start.bat`, åpne Test-04. Velg Rapport > Depotvurdering...
   Kontroller status for uttrekket og de native arkivdelene. Ingen automatisk
   godkjenning skal vises selv om alle deljobber er ferdige.
3. Test på en **kopi av Work** for å unngå faktisk faglig godkjenning:
   Opprett/velg brukerprofil, velg `Krever avklaring`, skriv grunn og bekreft.
   Kontroller `depot_assessment.json` ved vurdering av uttrekk og
   `depot_assessment_parts.json` for arkivdel.
4. Registrer en ny begrunnet beslutning, bekreft at historikktallet øker,
   og at tidligere beslutninger ikke forsvinner etter omstart.
5. Kontroller at Periodevurdering fortsatt gjelder riktig native arkivdel,
   og at valgte KDRS-kilder aldri forveksles med DWM-tall.
6. Test frakoblet Work, manglende rapport og samlerapportvalg med seks jobber.
   Gjenta visningstest med en større jobbliste.

Automatiserte kontrakttester omfatter revisjonsbinding, part-ID, Work-UUID,
historikk, manglende data, selvstendige omfang og versjon/Qt-kobling.
Full `test.bat` og faktisk Windows GUI-test gjenstår hos brukeren.
